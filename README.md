# LunarPilot

**Хватит ли времени на первые операции после посадки на Луну?** Выберите площадку и время, задайте длительность операций и посмотрите, сколько подряд центры Солнца и Земли будут выше местного горизонта. LunarPilot рассчитывает направления по данным JPL Horizons, строит горизонт по измеренному рельефу и показывает результат на шкале UTC, графике и трёхмерной Луне.

Проект для [NASA Space Apps Challenge 2026 · Lunar Landing Site Navigator](https://www.spaceappschallenge.org/2026/challenges/lunar-landing-site-navigator/). Интерфейс доступен на английском и русском.

## Быстрый запуск

Нужны Node.js 22+, браузер с WebGL2 для 3D-видов и интернет для получения новых данных JPL и DEM. Ключи API не требуются.

```sh
npm ci
npm start
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173). Сервер слушает только локальный адрес. Для настройки порта, таймаутов и контактного адреса для JPL сохраните копию [.env.example](.env.example) под именем `.env`. Без этого файла используются настройки по умолчанию.

## Демо за три минуты

Сравним **Odysseus** и **Athena** при одинаковом старте и одинаковых требованиях. Используйте пресеты с началом **14 ноября 2026, 00:00 UTC**, периодом **168 часов**, высотой аппаратуры **2 м** и требованием **4 часа** непрерывных операций. До показа выполните оба расчёта в том же браузере, чтобы открыть их из истории.

1. **0:00–0:40 · Выбрать площадки.** На глобусе покажите Odysseus и Athena, затем откройте их готовые расчёты из таблицы. Чтобы заполнить её при подготовке, выберите каждую площадку и нажмите **Open preset scenario**.
2. **0:40–1:55 · Сравнить один момент.** По очереди откройте результаты в **Chart** и установите ползунок на **15 ноября 2026, 07:00 UTC**, через 31 час от начала пресета. Полоса **Both** показывает пересечение окон Солнца и Земли, **Start** — минуты, с которых хватит времени на операции.
3. **1:55–3:00 · Объяснить результат.** Откройте **Surface view** и покажите, как гребень меняет горизонт по направлению к Солнцу. В расчёте Athena Солнце было примерно на **0,05°** выше гребня. Такой небольшой запас чувствителен к детализации рельефа.

| Площадка | Состояние в выбранный момент | Остаток совместного окна |
| --- | --- | ---: |
| Odysseus · IM-1 | Солнце закрыто рельефом | 0 ч |
| Athena · IM-2 | Оба центра выше местного горизонта | ≥137 ч |

Это результаты LunarPilot на сохранённых реальных ответах JPL и DEM при указанных настройках. Знак **≥** означает, что окно открыто до конца выбранного периода, **21 ноября в 00:00 UTC**. Момент закрытия по этому периоду определить нельзя.

### Поиск времени посадки

Укажите координаты и высоту аппаратуры, затем в **Find suitable landing starts** задайте границы UTC с точностью до минуты и необходимое непрерывное время операций. **Find starts** выполняет один расчёт на весь диапазон. Таблица показывает первый и последний допустимые старты, длительность окна и подтверждённый запас при первом старте. Кнопки **First start** и **Last start** открывают выбранный момент на общем графике и шкале. Сортировка и изменение необходимой длительности используют загруженные данные.

Для запросов к `/api/analysis` и `/api/sky` можно передать `end_utc` вместо `duration_hours`. Выберите один из двух параметров. Если конец диапазона приходится между отсчётами JPL, последнее положение интерполируется к запрошенной минуте до вычисления окон.


### Сравнение двух площадок

В **Compare two sites** задайте A и B координатами либо кнопками **Pick A/B on globe**. **Odysseus / Athena** заполняет координаты известных площадок. Общие начало и конец UTC, шаг 1–60 минут, высота аппаратуры и требование к длительности фиксируются при нажатии **Calculate A and B**. Максимум — 30 суток и 2000 интервалов; для длинного диапазона увеличьте шаг.

Обе полосы используют одну абсолютную шкалу UTC. Карточки показывают первый допустимый старт и остаток окна после операций. Кнопка с временем старта открывает тот же расчёт на основном графике и ставит ползунок на первую допустимую минуту окна. Результат A доступен, пока B ещё загружается или завершился ошибкой. Отдельно показаны отсутствие совместных окон, слишком короткие окна и подтверждённая только до конца периода видимость (`≥`). Правки формы помечают результаты как относящиеся к предыдущим параметрам. Переключение EN/RU сохраняет загруженные результаты.

Версия текущей геометрической модели с DEM — `centers-dem-v3`; плоского горизонта для базовых тестов — `centers-flat-v1`. Версия JPL API указывается отдельно в ссылках на исходные ответы.

## Как считаются окна

1. **Горизонт.** По DEM ищем максимальный угол подъёма рельефа в каждом из **720 направлений** с шагом **0,5°**, до **200 км** от площадки. Учитываем кривизну Луны и высоту аппаратуры над грунтом.
2. **Положение Солнца и Земли.** JPL Horizons даёт азимут и видимую угловую высоту каждого центра для той же точки и абсолютной высоты наблюдателя. [JPL Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html)
3. **Видимость.** Для каждого тела вычитаем угол горизонта в его направлении из угловой высоты центра. Положительная разность означает видимость. Между временными отсчётами расчёт учитывает пересечённые узлы профиля, чтобы учесть гребень между соседними отсчётами эфемерид.
4. **Окно операций.** Пересекаем интервалы видимости двух тел. Для заданного времени проверяем, хватит ли остатка окна на операции. Если старт пока невозможен, ищем ближайшую подходящую минуту в загруженном периоде.

**Учебный пример.** Центр Солнца на +1°, гребень в том же направлении на +3°. Разность −2°, и рельеф закрывает Солнце. Если Солнце видно с 08:00 до 13:00, а Землю с 10:00 до 16:00 UTC, совместное окно длится 3 часа, с 10:00 до 13:00.

<details>
<summary>Формула угла рельефа</summary>

Формула использует радиус Луны `R`, расстояние по поверхности `d`, высоту препятствия `h` и абсолютную высоту наблюдателя `ho`.

```text
angle = atan2((R + h) cos(d/R) - (R + ho), (R + h) sin(d/R))
```

`ho` равна высоте грунта плюс высота аппаратуры. Для каждого азимута берётся максимальный угол и интерполируется между соседними направлениями, включая шов через север. Допустим и отрицательный угол горизонта, например на возвышенности. [Код расчёта](lib/terrain-math.mjs)

</details>

### Границы модели

Окна описывают геометрическую видимость центров тел. Для расчёта энергии, радиолинии, затмений, частичной видимости дисков и пригодности грунта нужны дополнительные модели. Время границ окна зависит от сетки DEM, азимутов и временной интерполяции. Узкие препятствия могут остаться между отсчётами. Камни, микротекстура и обзорное усиление рельефа служат визуализации. **Шаг сетки DEM не равен точности измерений.**

Готовые обзорные карты входят в репозиторий. Команды подготовки находятся в [scripts/prepare_maps.py](scripts/prepare_maps.py) и [scripts/prepare_polar.py](scripts/prepare_polar.py). Высоты в расчёте отсчитываются от сферы радиусом **1 737 400 м** в системе MOON_ME / DE421. В ближней зоне полярные сетки 20 м используются южнее **80,05° S** и севернее **80,05° N**. На больших расстояниях шаг увеличивается. На точном полюсе заданная долгота определяет ориентацию местных направлений.

### Сеть и сохранённые расчёты

При первом расчёте сервер запрашивает диапазоны байтов GeoTIFF и ответы JPL, поэтому он может занять десятки секунд. Загруженные данные сохраняются в локальном `data/cache/`. При временном сбое JPL сервер делает до двух повторных попыток с паузой. Готовые строки истории доступны после обновления страницы в том же браузере. Ближний рельеф для прогулки загружается отдельно от дальних сеток и расчётного горизонта.

Пресеты могут обращаться к сети при пустом кэше. Данные в [data/demo](data/demo/) используются для воспроизводимых тестов. Переносимый [годовой офлайн-набор (#15)](https://github.com/fenzit/Lunar-Landing-Site-Navigator/issues/15) запланирован.

## Проверка и разработка

- `npm test` — тесты без интернета. Проверяют границы окон, ответы JPL, профиль рельефа, расчёты у полюсов и шва долгот, загрузку DEM и прогулку по поверхности.
- `node scripts/benchmark_surface.mjs` при работающем сервере — замер загрузки ближайшей сетки, дальнего рельефа и горизонта.
- Ручная проверка — прогон обоих пресетов по сценарию выше, затем **Surface view → WASD → Calculate here**. Новая точка потребует доступа к поставщикам данных.

Реализация на Node.js, Three.js и GeoTIFF.js. В основе интерфейса [макет команды](lunar-interface.html). Codex помог с кодом, подготовкой карт и проверками. Код распространяется по [лицензии MIT](LICENSE), научные данные сохраняют атрибуцию источников.
