# Domain docs

У проекта единый контекст. Глоссарий ведётся в корневом `GLOSSARY.md`, архитектурные решения — в `docs/adr/`.

- Перед работой с терминами прочитай глоссарий, если он есть. Используй его формулировки в спецификациях, задачах и тестах. Пока глоссарий отсутствует, опирайся на документацию и код проекта.
- Перед архитектурным изменением прочитай ADR, относящиеся к задаче. Если предлагаемое изменение затрагивает существующее решение, укажи номер ADR и опиши расхождение.
- Добавляй новые термины и решения по мере их согласования в рамках `domain-modeling`.
